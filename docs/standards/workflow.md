# 开发流程

先读取当前任务、项目入口和涉及系统的文档，再通过 IDEA 查询实际源码、类型与调用关系。存在影响实现的歧义时一次只确认一项；已有明确授权不重复询问。

优先使用 IntelliJ IDEA、IntelliJ index、MCP/API。源文件、资源、Gradle 和文档通过 IDEA 编辑；类、包、成员迁移使用语义重构。命令行只补足 IDE 不提供的能力，不能绕过可用的专用工具。

保留既有暂存与未暂存修改。新文件使用新增补丁，已有文件使用行级补丁；上下文匹配失败时停止、读取并报告。删除前保留可恢复备份。保留原编码、换行及未涉及部分的排版。

默认只读取编辑器诊断。编译、构建、Data、测试、同步、重载和游戏运行分别按当前任务的明确授权执行；不可将某次重构的授权当作以后任务的默认授权。

先完成本次授权范围内的全部代码修改，再统一检查正确性，最后执行已获授权的验证。新增代码和本次修改行在编辑阶段按项目规范处理格式，不扩大到未修改区域，不额外优化导入或重排成员。检查或验证发现本次引入的问题时，先完成修正及其格式处理，再重新检查和验证；这不扩大主动验证授权。

Data 管理的输出只能修改生成源并通过获批的 Data 生成，不手工修补生成结果。只报告实际执行的操作、诊断、运行结果、未完成项和备份。

Git 提交仅包含本批授权内容。存在混合暂存基线时不得直接 add 全部或提交全部，也不得重置用户索引以制造干净工作区。
