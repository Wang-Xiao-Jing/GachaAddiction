# Java 与包职责

保持 Java 21 的正式语法和当前项目格式。条件与循环使用大括号，逻辑阶段之间留空行；尽量通过提前返回减少嵌套，保持求值顺序、异常、资源与线程所有权。

使用明确 import 和简洁类型名称；常规顶层接口以 I 开头，Mixin Accessor、框架桥接与内部回调遵循其框架约定。纯工具类以 Util 结尾，放在根 util 包及其子包。

注册入口集中在 registry；领域注册容器不因名字包含 Registry 就机械移动。自动事件订阅入口放在 events 及按领域划分的子包，自定义事件类型放在 event；每个具体事件在相同总线与发行侧只保留一个入口，再显式分发。

客户端实现位于 client，客户端注册入口位于 registry/client；公共模型、数据编解码与服务器逻辑不能引用客户端实现。第三方适配位于兼容模块，通过实际需要的接口接入，避免公共层反向依赖可选库。

业务资源 ID、可独立调整或多处复用的规则值归于其注册、配置或生命周期所有者。语言语法、协议格式、框架签名和清楚的一次性局部计算不机械提取常量。不改变已有声明的修饰符来满足个人风格。

不改变稳定注册 ID、资源路径、网络字段顺序、数据键与玩法时序。历史 API 或格式的删除必须在当前任务已确认的兼容策略内，当前源码没有引用不证明外部没有使用。

生成资源和第三方资产不批量格式化；行为修复与结构迁移分别记录和验证。
