# 场景来源、箱盖覆盖与渲染目标

## 责任和调用

| 入口 | 责任 |
| --- | --- |
| GachaSceneSources | 唯一待消费来源、世界/菜单/5000ms 校验、替换界面时重新记忆 |
| GachaChestRenderOverride | 箱盖临时覆盖的线程作用域、上一层覆盖恢复、Mixin 读取 |
| GachaSceneTargets | 箱体和倒影两个目标的分配、尺寸更新、关闭与主目标恢复 |
| GachaSceneRenderer | 组织实际场景绘制、单帧箱体缓存、光照与几何、倒影合成及轮廓调用 |

输入事件和展示替换直接调用来源组件。箱盖相关两个客户端 Mixin 直接读取覆盖组件，不再借场景渲染器取得临时状态。场景实例仍通过 rememberForReplacement 传递它实际使用的箱体来源，因为来源可能已在渲染失败时回退。

## 来源消费

记忆方法通过 IDEA 成员移动连同私有 pending 和记录类型一起迁移；四个记忆/清理方法体与提取前一致。takeSource 先取出并清空待消费记录，再核对当前世界、年龄和需要的新菜单，最后返回仅含有效箱体及展示物品的 CapturedSource。

原有 5000ms、同世界引用比较、菜单实例和 containerId 条件均保留。ItemStack 仍在记忆时复制为数量 1；消费时不增加新的深拷贝或修改展示组件。丢失、过期和菜单不匹配的来源仍被消费并丢弃。

## 箱盖作用域

原实现已经保存并恢复 previous 覆盖，嵌套恢复并非本批新增行为。当前用 AutoCloseable 作用域表达同一状态栈：构造时保存 previous 并设置当前两个箱体及 opening，关闭时恢复 previous 或清空线程状态。

作用域包围 PoseStack 初始化和模型绘制，异常退出也会执行恢复。原箱体位移、朝向、相邻箱体偏移和绘制顺序逐项比较一致；两个 Mixin 的原目标方法和返回条件没有改变。

IDEA 移动内部记录后，pending 和 ThreadLocal 声明残留了两个旧限定类型名，造成 12 个类型诊断；已按当前类归属修正，最终检查无错误，没有忽略冲突或保留旧记录壳。

## 目标与关闭

目标尺寸继续与实际输出目标比较，变化时先销毁旧目标，再建立同样带深度附件、透明清除色的 TextureTarget。Renderer 通过局部引用使用目标；清除、绑定、投影、绘制和合成仍按原顺序执行。

关闭顺序保持轮廓、倒影目标、箱体目标。try-with-resources 确保某项关闭异常时仍尝试关闭后续资源，并保留受抑制异常；目标释放 finally 继续绑定 Minecraft 主目标，再退出 GachaRenderState。

TargetRelease 是私有内部关闭回调，只用于无检查异常的两项目标释放；不是新的全局资源系统。没有目标时仍直接返回，不分配或读取无用目标。
