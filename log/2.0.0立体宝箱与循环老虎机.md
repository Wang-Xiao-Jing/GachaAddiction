## 已实现

- [x] 宝箱使用45°俯视和45°水平偏转的三维模型，保留原有四次点击解封操作；开盖演出调整为1.4秒，点击或空格可跳过。
- [x] 客户端记录最近一次右键箱子的来源。来源方块属于ChestBlock、方块实体属于ChestBlockEntity及其子类，且打开的是新的对应菜单时，直接调用已注册的方块实体渲染器。
- [x] 原版普通/陷阱宝箱与继承箱子类的模组宝箱沿用对应渲染器；双箱同时绘制两半。没有有效箱子来源、来源已失效、不是箱子类或来源渲染失败时使用原版普通宝箱。
- [x] 开盖角度通过仅客户端的ChestBlockEntity.getOpenNess注入，在当前场景绘制期间临时提供；同时覆盖双箱两半，finally恢复作用域，不修改箱盖控制器、库存、方块状态或服务端数据。
- [x] 光效采用带深度测试、关闭深度写入的加色三维光束与立方粒子，与宝箱使用同一三维变换；宝箱和物品会遮挡光效。该光效不是给世界方块添加动态点光源。
- [x] 开盖后最多五个物品沿三维弧线由箱内跳出，并从小变大；容器使用已收到的奖励快照，专用道具未结算前仍只用演示图标，最终汇总保留全部实际奖励。
- [x] 图腾使用有厚度的分段模型与宝石凸起，复用原AI纹理，以原版ItemRenderer的NONE展示上下文绘制，绕三轴摇摆；保留约2.4秒进入/退出时序。
- [x] 按后续要求恢复现代着色器的原固定中心底光，保留黑色剪影、全屏稀有度雾光/粒子和轮廓描边，揭晓闪光仍保留。现有代码没有单独的矩形底板，实际观感仍需游戏内确认。
- [x] 旧老虎机继续使用slot_machine，保留纵向多转轮布局，接入现代PostChain背景、原版物品透明渲染与ColorTooltips完成边框。
- [x] 真实奖励先保存在展示快照中，滚动期只绘制候选图标与中性边框，不提前显示真实奖励数量、组件、结果边框或结果悬浮。
- [x] 点击或空格开始所有转轮减速，之后才将真实物品插入停止队列；再次点击或按空格可以快速完成。结尾自动进入现代汇总。
- [x] 每个转轮按物品类型去重，每轮用完后重新洗牌，跨轮首尾避免紧邻重复；只有一个候选时在轮间加入空白间隔，避免连续重复同一图标。没有候选时使用集中定义的演示物品。
- [x] 循环仅保留有限窗口和一轮候选，不随观看时间增加队列；只创建当前屏宽允许的转轮，超出前段容量的实际奖励在现代汇总中完整显示。
- [x] 已接收首次快照后，容器自动拿取引发的后续内容同步不重建演出或提前关闭动画。自动拿取仍只按容器OPEN边界处理。
- [x] 现代汇总保持16像素物品、18像素外框、1像素间距、逐件出现、点击加速、空格全部出现、滚动与置顶悬浮。
- [x] 保留独立的新三轴类型interactive_slot_machine及代币绑定，不更改其交互和抽奖规则。

## 来源与兼容边界

箱子来源来自当前客户端右键事件，限定为五秒内的新菜单，来源失效时回退普通箱子；不新增网络消息或区块加载。未通过右键箱子打开的虚拟容器与专用道具使用普通箱子。

标准继承ChestBlockEntity.getOpenNess的模组箱子复用开盖时序。模组若完全重写箱盖读取或渲染器、绕开该方法，仍需针对该模组进行游戏内兼容验收；不能凭继承关系保证所有自定义渲染器一致。渲染抛出异常时该场景后续回退普通箱子，记录一次异常。

本轮模型改动仅涉及祈愿图腾的JSON模型，未改动生成的PNG。图腾由13个分段/凸起组成，避免为高分辨率透明纹理逐像素挤出。其余AI道具图集尺寸/mipmap问题仍待原有资源验收。

原有六张图片是早期设计预览，尚未更新为本轮3D效果截图，不作为此次视觉验收结果。
