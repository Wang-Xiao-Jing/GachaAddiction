## 已确认的证据

- 现有run/logs/latest.log记录了模组加载线程中的配置资源初始化错误：No payload found for class net.minecraft.network.chat.Component。
- 调用链为GachaAddictionClient构造、LDLib2Util.createConfigScreenFactory、LDLib2ConfigScreen.registerResources、LDLib2ConfigPackProvider.register、FileResourceProvider构造、模板反序列化。
- 依赖源码显示Component等访问器由LDLib2的CommonProxy.init中的AccessorRegistries.init注册。注册配置工厂时立即读模板不能依赖其他模组构造完成，尤其在并行加载期间。
- 自定义渲染收尾曾直接enableBlend/defaultBlendFunc/enableDepthTest，转盘曾直接enableCull，不能恢复调用前的真实状态。
- 原版GuiGraphics.flush本身会改变深度测试状态。因此状态快照必须位于flush之前，也必须覆盖不透明物品和整个嵌入式转轮控件，不能只覆盖半透明物品路径。
- 原版EffectInstance和ShaderInstance分别缓存着色器程序；后处理clear会解绑程序，需要使普通ShaderInstance缓存失效。原版VertexBuffer绘制时执行setDefaultUniforms、apply、draw、clear；退出保护时只恢复逻辑引用，不提前apply旧缓存。

以上证明存在初始化错误与状态隔离缺口，尚未通过修复后的游戏运行确认其与全部截图症状一一对应。
