# 开箱播报背景资源包

适用版本：Minecraft Java 1.21.1 / NeoForge 21.1.249。资源包格式为 34，沿用原版资源包启用和重载流程。

## 两种独立背景

| 显示方式 | GUI sprite ID | 资源包中的 PNG 路径 |
|---|---|---|
| 右上角 Toast | gachaaddiction:announcement/toast | assets/gachaaddiction/textures/gui/sprites/announcement/toast.png |
| 中上方滚动条 | gachaaddiction:announcement/banner | assets/gachaaddiction/textures/gui/sprites/announcement/banner.png |

每张图片旁边分别放置自己的 .png.mcmeta。两者独立替换，支持不同图案、透明度和缩放规则；资源包只包含其中一张及其元数据时，只修改对应的显示方式。

默认两张背景从当前 1.21.1 的原版 toast/advancement.png 原样复制，各为 160×32、157 字节，SHA-256 均为 15A959D338D8CE98C1381F95D34F7143377669BCADAE1198900BEA88144D6634。它们是模组内的两个独立文件，绘制时使用上表模组 ID，原版进度提示继续使用自身资源。

源文件可作为编辑模板：

- [toast.png](../src/main/resources/assets/gachaaddiction/textures/gui/sprites/announcement/toast.png)
- [toast.png.mcmeta](../src/main/resources/assets/gachaaddiction/textures/gui/sprites/announcement/toast.png.mcmeta)
- [banner.png](../src/main/resources/assets/gachaaddiction/textures/gui/sprites/announcement/banner.png)
- [banner.png.mcmeta](../src/main/resources/assets/gachaaddiction/textures/gui/sprites/announcement/banner.png.mcmeta)

## 资源包目录

~~~text
自定义播报背景/
├── pack.mcmeta
└── assets/
    └── gachaaddiction/
        └── textures/
            └── gui/
                └── sprites/
                    └── announcement/
                        ├── toast.png
                        ├── toast.png.mcmeta
                        ├── banner.png
                        └── banner.png.mcmeta
~~~

pack.mcmeta 示例：

~~~json
{
    "pack": {
        "pack_format": 34,
        "description": "GachaAddiction announcement backgrounds"
    }
}
~~~

将文件夹或 ZIP 放入当前游戏实例的 resourcepacks 目录，在资源包界面启用。ZIP 的根目录直接包含 pack.mcmeta 和 assets；启用后可按原版方式重新加载资源。

## 按物品自动选择背景

所有资源包在固定路径 assets/gachaaddiction/announcement/backgrounds.json 声明规则；模组内置文件的 rules 为空，未命中时使用前述默认背景。

~~~json
{
    "rules": [
        {
            "match": [["minecraft:diamond[minecraft:custom_data={legendary:1b}]"]],
            "toast": "my_pack:announcement/legendary_toast",
            "banner": "my_pack:announcement/legendary_banner"
        },
        {
            "match": [["minecraft:diamond"]],
            "toast": "my_pack:announcement/diamond_toast"
        },
        {
            "match": [[">=2"]],
            "toast": "my_pack:announcement/rare_toast",
            "banner": "my_pack:announcement/rare_banner"
        }
    ]
}
~~~

- match 沿用黑白名单的二维条件结构：内层条件全部满足，外层分组满足任意一组即可。例：[[">=2", "!minecraft:diamond"], ["minecraft:nether_star"]]。
- 支持物品 ID、#命名空间:标签路径、!物品或 !#标签，以及 =、>、>=、<、<= 稀有度比较；单独整数表示等于。稀有度使用现有 RarityUtil 的等级，兼容当前已接入的稀有度模组。
- 1.21.1 的物品数据使用原版物品组件语法，例如 minecraft:diamond[minecraft:custom_data={legendary:1b}]。指定的每个组件按完整值相等判断；custom_data 含额外键时不会命中上述示例。未指定的其他组件不影响匹配。字符串中的 JSON 双引号须按 JSON 规则转义。
- 每条规则至少提供 toast、banner 之一；两种背景分别选择第一条命中的有效目标。一个规则只写 toast 时，banner 会继续检查后续规则。
- 目标值为 GUI sprite ID，不带 textures/gui/sprites/ 前缀和 .png 后缀。例如 my_pack:announcement/rare_toast 对应 assets/my_pack/textures/gui/sprites/announcement/rare_toast.png，元数据放在其旁边的 rare_toast.png.mcmeta，缩放规则与默认背景一致。
- 将具体物品或组件条件放在通用稀有度条件之前。match 或分组为空不会作为通配规则；需要通用回退时直接替换默认背景。

规则文件必须使用 gachaaddiction 命名空间的固定路径，目标纹理可以使用资源包自己的命名空间。条件由接收者的资源包应用到收到的物品；发送者仍决定播报哪些物品。

## 多个资源包的合并顺序

同一路径的规则文件使用 ResourceManager.getResourceStack 全部读取并合并，不按单文件覆盖。按资源包优先级从高到低拼接，各包内仍按 rules 数组从上到下匹配；规则没有覆盖 ID，也不会按内容去重。

例如高优先级包 A 提供“钻石 → A 的右上角背景”，低优先级包 B 提供“稀有度 >=2 → B 的右上角和中上背景”。符合稀有度的钻石会使用 A 的右上背景和 B 的中上背景，其他符合稀有度的物品仍可使用 B 的两种背景。高优先级包的空 rules 不会清空低优先级包。

原版资源过滤器仍有效。同名 PNG 和 .png.mcmeta 的冲突遵循原版资源优先级；合并的是规则列表。各包使用自己的纹理命名空间可以避免同名图片互相覆盖。

非法 JSON 文件会记录来源包并跳过；单条非法条件只跳过该条规则。目标 ID 非法或 PNG 缺失时，记录来源包、从 0 开始的规则索引及目标，继续寻找该显示方式的后续可用目标。两种显示方式各自未命中时使用自己的默认背景。

规则通过客户端原版资源重载监听器读取。每条播报缓存选择结果，规则重载后重新选择；每帧绘制不重复匹配或解析 NBT。已显示的原版 Toast 不会因为规则重载重新计时。

## 背景缩放规则

绘制使用原版 GuiGraphics.blitSprite，由每张 PNG 自己的 gui.scaling 元数据决定缩放。默认两个 .png.mcmeta 内容相同，互不引用：

~~~json
{
    "gui": {
        "scaling": {
            "type": "nine_slice",
            "width": 160,
            "height": 32,
            "border": 4
        }
    }
}
~~~

- width、height 为背景的逻辑尺寸；默认 160×32。
- border 为保留的边缘尺寸。统一数值 4 表示四边都保留 4 个逻辑像素。
- 九宫格会保留边角并按原版规则绘制边缘和中间区域，适应提示宽度。
- 可将 border 改为含 left、top、right、bottom 的对象，四边分别使用非负整数；左右之和须小于 width，上下之和须小于 height。
- 更高分辨率的等比例 PNG 可以保持原逻辑尺寸。改变切片设计时同步修改该图片的元数据。
- 原版也支持 stretch 和 tile；未提供 gui.scaling 时采用原版默认的整图拉伸规则。元数据格式错误由原版资源加载流程报告。
- 纹理本身的透明像素用于控制背景透明度；渲染层不再叠加固定纯色底或稀有度侧边条。

例如完全拉伸可使用：

~~~json
{
    "gui": {
        "scaling": {
            "type": "stretch"
        }
    }
}
~~~

## 显示与绘制顺序

右上角实现原版 Toast 接口，由原版 ToastComponent 负责滑入、滑出、提示音和空位安排，与游戏其他 Toast 共用排位。模组复用最多三个播报槽位，按稀有度及到达时间选择消息；原版 ToastAddEvent 取消结果会被尊重，未成功加入的消息不重复提交。

右上角显示时间从原版实际显示阶段计算，使用播报 seconds 配置并乘以原版“通知显示时长”倍率，排队期间不提前消耗展示时间。中上方仍按自己的 seconds 配置从右向左滚动，不跟随右上角的排位或时间倍率。

两者均按“背景 → 文字 → 物品图标及数量”的顺序绘制，物品固定在文字区域右侧末尾。右上角长文字仍在内部平移，中上方文字仍滚动；文字裁剪不覆盖末尾图标。

打开聊天等具有鼠标的界面后，可以悬浮物品名称或末尾图标查看完整物品提示，继续使用接收者的播报悬浮开关和高级提示设置。Toast 滑入滑出时按实际绘制位置计算悬浮和裁剪范围。

资源包控制背景匹配、外观及切片方式；面板位置、图标位置、文字颜色和显示时长继续由现有客户端界面与配置控制。
