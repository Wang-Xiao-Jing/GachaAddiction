## 配置与持久化

| 位置 | 键 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 来源设置 | `gacha_type` | 缺省 | 指定该来源的动画；缺省保留原有打开条件和客户端选择 |
| 来源设置 | `force_watch` | `false` | 本来源要求完整观看 |
| SERVER | `presentation.force_watch` | `false` | 与来源强制标记取或 |
| SERVER | `presentation.protect_loot` | `true` | 服务端允许防抢 |
| CLIENT | `gachaa_screen.protect_loot` | `true` | 玩家请求防抢；与服务端许可取且 |

方块实体、实体使用 NeoForge Data Attachment `gachaaddiction:gacha_source` 持久化。物品沿用 `minecraft:custom_data.gachaaddiction`，与已有的 `card_pool`、`package`、`preview_items` 共存。锁只属于服务端本次会话，不写入存档。

来源显式指定非空动画时，容器每次打开都展示当前内容。未配置动画时继续采用原有战利品首次打开条件。`gachaaddiction:empty` 关闭该来源的展示；已触发展示且被要求强制观看时，空类型回退现代。服务端强制开关只约束已经触发的抽奖展示，不把所有普通界面变成抽奖。

双箱保留两半战利品表及打开标记。动画类型优先取第一半的明确配置，否则取第二半；强制标记取两半的或；通过合并来源能力写设置会写入两半。防抢锁覆盖两半。

原来的 COMMON 自动拿取开关保持双端独立，其服务端复核和 OPEN/COMPLETE 边界继续沿用。

## 能力 API

公开接口：`api/IGachaSource.java`；设置：`api/GachaSourceSettings.java`；注册与默认适配：`registry/GachaSources.java`。

- `GachaSources.BLOCK`：方块实体能力。
- `GachaSources.ENTITY`：实体能力。
- `GachaSources.ITEM`：物品能力。
- `getSettings` / `setSettings`：读写动画与强制标记。
- `getDisplayItem`：返回本次演出应显示的触发方块或物品。
- `getLockTarget`：返回具有稳定对象身份的实际来源，供临时锁使用。
- `inspect` / `opened`：容器打开数据及旧战利品打开标记适配。
- `beginDraw`：专用道具复用现有卡池准备、确认与消耗流程。

以下是Java调用片段，依赖调用方已有的level、position、entity和stack上下文，不是独立编译单元：

```text
IGachaSource source = level.getCapability(GachaSources.BLOCK, position);
if (source != null) {
    source.setSettings(new GachaSourceSettings(
            Optional.of(GachaTypes.CHEST.getId()), true));
}

IGachaSource entitySource = entity.getCapability(GachaSources.ENTITY);
IGachaSource itemSource = stack.getCapability(GachaSources.ITEM);
```

扩展模组在 `RegisterCapabilitiesEvent` 注册自己的 provider。默认适配在 LOWEST 优先级注册，保留其他 provider 先提供能力的机会。能力自身不负责保存数据：默认实现用 Attachment/CustomData 保存，扩展 provider 应自行持久化。调用方应从 Level、Entity、ItemStack 查询，不缓存会失效的世界能力。

服务端在打开会话时发送动画、强制标记、触发物快照及副类型偏好，客户端无需复制来源持久化数据。可选通道为`presentation`、`presentation_control`、`presentation_preferences`；后续结果包已增加真实分轮字段，完整规则依赖对应主协议4及双端通道支持。

## 服主设置示例

原版战利品箱并指定上划开箱动画：

```mcfunction
/setblock ~ ~ ~2 minecraft:chest{LootTable:"minecraft:chests/end_city_treasure","neoforge:attachments":{"gachaaddiction:gacha_source":{gacha_type:"gachaaddiction:chest",force_watch:1b}}}
```

修改现有方块实体的设置：

```mcfunction
/data merge block ~ ~ ~2 {"neoforge:attachments":{"gachaaddiction:gacha_source":{gacha_type:"gachaaddiction:csgo",force_watch:0b}}}
```

专用道具示例（先由服主部署[独立测试包](test-packs/secondary-interactions.zip)，或使用自己的有效卡池与套餐）：

```mcfunction
/give @s gachaaddiction:wheel_ticket[minecraft:custom_data={gachaaddiction:{card_pool:"gacha_test:secondary_demo",package:"gacha_test:single",gacha_type:"gachaaddiction:wheel",force_watch:1b,preview_items:["minecraft:diamond","minecraft:emerald"]}}]
```

道具选择现代、旧老虎机或LDLib2类型时，先按原有服务端事务确认，再展示真实结果；交互前段在触发完成后确认。宝箱和图腾副类型按小总览/总总览分层，交互时机不改变概率、奖品、保底和倍率。

## 观看与防抢生命周期

强制观看禁止 Esc 提前退出、空格/Shift 跳过、重复点击快速完成及汇总加速；保留正常揭晓、切换、上划开箱、点击启动、拨动启动和旧老虎机开始停轮。现代揭晓播放完才能切到下一件；汇总全部物品自然出现后允许关闭。失败、死亡、断线、换维度、来源移除或五分钟超时会释放限制。

防抢在服务端允许且开箱者客户端启用时建立；防抢与强制观看互相独立。覆盖其他玩家新开界面、已经打开界面的槽位操作、原版漏斗取出、发射器/投掷器触发，以及 NeoForge 方块/实体/物品的 ItemHandler 提取。已缓存的处理器包装器也在每次提取时查询锁。其他玩家破坏来源方块或攻击来源实体会被阻止。

完成、非强制取消、菜单由服务端关闭、掉线、死亡、换维度、来源移除、超时和服务器停止均清理锁。专用道具仍沿用原有服务端消耗校验；观看完成消息只表示客户端演出状态，不证明屏幕实际显示了哪些像素。

兼容模组绕过菜单及 ItemHandler、直接改写原始库存的路径需要对应适配；爆炸和世界移除仍可结束来源。未运行双人、漏斗及自动化用例，不能把接入完成写成全模组防抢验收通过。
