# 2.0.0 开箱播报

> 播报格式、链路和配置仍有效；当前主协议为4，历史Data键数及阶段诊断只代表当时结果。当前统一待办见[主计划](2.0.0计划.md)，验收入口见[清单](2.0.0验收清单.md)。

日期：2026-10-19。目标项目：Minecraft 1.21.1 / NeoForge 21.1.249。

## 已确认的行为

- 发送者决定播报哪些物品；接收者只决定显示方式、时长和是否启用悬浮详情。
- 自动候选复用发送者的白名单和最低稀有度，二者为“或”。默认最低等级为 RARE（2），使用现有 Confluence Magic Lib / RarityCore / 原版兼容顺序。
- 同物品、同组件的奖励合并数量，每次开箱仅选择最稀有的最多 3 种，其余不排队播报。
- 聊天栏、右上角提示、屏幕中上方滚动条分别开关，可以同时开启，也可以全部关闭。
- 无法确认所属结构时使用世界（维度）名称。
- Alt 手动播报鼠标悬浮的已揭晓奖励，不受自动播报稀有度、白名单或自动开关限制。
- Alt 只在本次开箱会话的当前可视界面生效。动画返回同一菜单的原容器属于同一次开箱，保留快照并将操作目标切到容器；真正关闭容器、切换到无关界面或打开其他菜单后清空快照。
- 可手动播报的真实容器奖励槽位在背景层绘制淡绿色边框，颜色 RGB 为 #90EE90，透明度为 0.3（ARGB #4D90EE90）。转轮动画和本地预览不绘制播报边框；玩家库存槽位不参与容器标记。
- 已发送的聊天和接收端短暂提示不随发送者关闭界面撤销；退出登录清空客户端提示列表。

## 格式与名称

~~~text
玩家名称在结构名称中的箱子名称中开出物品稀有度物品物品名称
玩家名称在结构名称中的箱子名称（重命名名称）中开出物品稀有度物品物品名称
~~~

无法识别结构时，结构位置替换为维度名称。物品数量保留在完整 ItemStack 中，悬浮详情和提示图标数量使用实际选择数量。

服务端获取玩家显示名、容器原名、重命名和容器位置，不接受客户端传入玩家名称或来源文字。双箱保留“大型箱子”原名；存在重命名时取原版双箱展示使用的那一半名称。实体容器使用实体类型名称。

维度直接调用当前 NeoForge 的 Level#getDescription()，发送保留翻译键的 Component，由接收端按自身语言及资源包解析。维度 API 内部使用 Level#getDescriptionKey() 和 ILevelExtension.TRANSLATION_PREFIX；按此次要求，本模组也生成主世界、下界、末地三个标准维度键的中英文译文。

结构优先使用资源 ID 对应的现有标准翻译键；缺失时读取本模组自己的 34 种原版结构中英文回退。回退键位于 gachaaddiction.structure_fallback.<namespace>.<path>，不覆盖其他模组或资源包的标准键。当前 1.21.1 的 Structure 本身没有维度那样的 getDescription() 方法，因此使用 ResourceLocation#toLanguageKey 生成键：

~~~text
structure.<namespace>.<path，斜线转点>
dimension.<namespace>.<path，斜线转点>
~~~

Wiki、原版完整语言文件和指南针模组的逐项证据见 [结构与维度翻译核对](2.0.0结构与维度翻译核对.md)。原版 Java 1.21.1 没有内置 structure.* 译名；已按确认的 A 方案补齐本模组独立的原版结构回退生成源。

标准键和本模组回退键均无译文时显示完整资源 ID，不根据战利品表名称猜测结构。结构识别只检查已加载区块的结构起点和实际结构片段；起始区块未加载、容器不在结构片段内、无法识别结构时回退到维度。多个结构重叠时按结构 ID 字典序确定一个名称。

稀有度显示复用对应兼容来源：Confluence 名称、RarityCore 本地化提示或原版稀有度名；颜色复用现有 RarityUtil。RarityCore 显示文字可能包含其自定义的稀有度提示前缀。

## 客户端配置

配置位于 CLIENT 的 announcement 节，不同步接收者设置。

| 配置 | 默认值 | 作用 |
|---|---|---|
| automatic | true | 本机开箱后自动选择并请求播报 |
| chat | true | 在本机聊天栏显示收到的播报 |
| toast | false | 右上角提示 |
| banner | false | 屏幕中上方横向滚动条 |
| tooltips | true | 悬浮物品名称或提示图标时显示完整物品信息 |
| seconds | 8 | 提示和滚动条时长，范围 1—60 秒 |

自动候选继续使用 gachaa_screen.whitelist_filter_list 和 gachaa_screen.minimum_reward_rarity，与动画触发黑名单和自动拿取开关分别处理。接收者不会用自身白名单、稀有度阈值或 automatic 开关过滤别人发来的物品。

聊天物品名使用原版 SHOW_ITEM。提示及滚动条使用完整物品组件和原版 Tooltip 渲染，跟随接收者的高级物品提示及物品提示事件。游戏中鼠标被锁定时可直接观看；打开聊天等有鼠标的界面后可悬浮名称查看。

右上角接入原版 ToastComponent 的滑入滑出、提示音及排位，中上方保留独立滚动。两者各选择最多 3 条，优先稀有度，其次新到达消息；右上角复用三个播报对象，避免额外队列不断增长。物品图标固定在文字右侧末尾，背景、文字、物品依次绘制。两种背景均使用独立的模组纹理和原版 GUI sprite 元数据，资源包规则见 [播报资源包说明](2.0.0播报资源包.md)。

## 链路和会话

~~~text
服务端创建真实奖励/容器菜单
  ├─ 保存本次实际奖励、来源和随机 token
  └─ 给开箱者发送 token + 菜单 ID
         ↓
原有容器/奖励同步到客户端
         ↓
发送者按本地规则选出最多 3 种，或在当前结果界面悬浮奖励按 Alt 选出 1 种
         ↓
服务端从连接识别玩家，核对 token、当前菜单、维度和实际奖励快照
         ↓
向协商了播报通道的在线客户端转发完整物品组件和来源
         ↓
接收者按自身开关显示聊天、提示和滚动条
~~~

- 自动每次会话最多成功播报一次；手动每次请求最多一个物品，服务端间隔至少 20 tick，客户端过滤 Alt 长按重复。
- 服务端不重新执行接收者或服务端稀有度/白名单筛选；只验证物品确实来自该次开出结果，并将数量限制到实际快照。
- 自动拿取发生后也可使用开箱时快照核对，不依赖物品仍留在原槽位。
- 客户端将快照绑定到当前开箱菜单及其可视 Screen。实际界面切换完成后再判断生命周期，同一菜单的动画与容器之间切换只重新绑定显示目标。真正退出时发送带原 token 的清理请求；服务端只清理匹配快照，避免旧界面请求误删新会话。
- 服务端关闭真实容器、打开另一个菜单、登出或停止服务器时清理对应会话。
- 会话最长有效期 6000 tick；超时请求被拒绝。没有新增磁盘日志、历史记录、后台或持久化事务。
- 快照最多处理 4096 个源栈，组件相同的物品使用原版哈希策略合并；每位玩家只保存一个会话。
- 可播报背景边框使用物品组件哈希集合查询，避免每帧逐个扫描整份奖励快照。
- 会话包不重复发送整个容器奖励；奖励沿用原有同步。请求及播报包最多 3 栈。
- 三个播报通道均为optional；当前主注册版本为4，播报通道没有因后续分轮展示改变字段，未协商时不发送。

## 容器绿色框与 Alt 修正

根据实际界面反馈，将播报边框从原版/LDLib2 共用的转轮控件移除，仅保留真实容器槽位的淡绿色背景边框，透明度 0.3。

修正前 ScreenEvent.Closing 会先清理会话，随后 MinecraftMixin 才将动画退出目标改为原容器，导致返回箱子时已经没有可用快照。现在在 Minecraft#setScreen 返回后读取最终界面；每帧也检查当前界面以覆盖 GUI 图层切换。同一真实菜单下的动画、原容器及界面回退只转移绑定；离开本次容器或切换无关界面时清理。
