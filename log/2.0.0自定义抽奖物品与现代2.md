## 现代2

类型 ID 为 `gachaaddiction:modern_2`，与原 `modern` 独立，可通过现有客户端动画选择和来源 `gacha_type` 使用。

- 同一页的物品同时进入剪影和揭晓阶段；点击揭晓本页，再次点击进入下一页，最后进入原现代汇总。
- 展示区域单行排列，最小宽度64 GUI像素，间隔8 GUI像素；宽高随窗口可用空间确定，可以是长方形。
- 物品统一缩放，按展示区域的长边决定渲染尺寸，不做非等比拉伸；超出该区域的物品部分在离屏物品层内裁剪。物品名称也限制在本区域，完整信息可悬浮查看。
- 每页容量由最小宽度和间隔计算，放不下的物品整体进入下一页，不缩成小于64像素的小格。页面末尾不足一排时居中。
- 滚轮翻页；右方向键或点击继续，左方向键返回；空格加速揭晓，Shift进入汇总。强制观看时不能跳过尚未揭晓的页。
- 排序、合并、自动拿取及奖励结算继续使用现有流程；分页不额外抽奖、扣费或发奖。

## 通用物品与数据包定义

采用已确认的B方案：不为每个定义注册新物品ID，使用现有 `GachaDrawItem` 作为载体，通过 `minecraft:custom_data` 组件中的 `gachaaddiction.draw_item` 引用定义。

定义路径为 `data/<namespace>/gacha_items/<path>.json`，定义 ID 为 `<namespace>:<path>`。此目录独立于现有 `gacha/` 规则目录。

示例 `data/gacha_demo/gacha_items/olive_ticket.json`：

```json
{
    "card_pool": "gacha_demo:custom_items",
    "package": "gacha_demo:triple",
    "source": {
        "gacha_type": "gachaaddiction:modern_2",
        "force_watch": false
    },
    "item": {
        "id": "gachaaddiction:wish_totem",
        "count": 1,
        "components": {
            "minecraft:item_name": "星辉抽奖券",
            "minecraft:custom_model_data": 1
        }
    },
    "preview_items": ["minecraft:diamond", "minecraft:emerald", "minecraft:enchanted_book"]
}
```

`card_pool` 和 `package` 必填；必须指向已部署的卡池和套餐。示例包同时提供这两个定义，不依赖其他测试包。

`source` 复用现有来源设置，支持 `gacha_type`、`force_watch`、`secondary_type`、`choice_count`；副类型仍只作用于箱子和图腾。`item` 可省略，默认使用祈愿图腾；若填写，其 `id` 必须是模组现有五种抽奖物品之一。生成时数量固定为1，数量由发放入口控制。`components` 使用当前版本原版 ItemStack Codec，支持名称、外形模型值等组件。`preview_items` 可省略。

服务端使用时重新解析定义，读取卡池、套餐和来源规则；定义不存在时拒绝抽奖，不从物品上的旧绑定继续扣费。JSON格式或字段无效时，本次定义重载失败，保留上次完整的物品定义集合。直接写入 `card_pool` / `package` 的旧物品仍可用。

定义通过现有数据包重载生命周期读取，本轮未实际执行重载。修改外形模板后，已发放物品保留其已有外形组件；需要重新发放才能获得新模板。规则在下一次使用时读取当前定义。

### 发放

安装示例数据包后，由具备现有 `MANAGE_ADMIN` 能力的来源执行（默认权限等级4，服主控制台可用）：

```mcfunction
/gacha item give @s gacha_demo:olive_ticket 1
/gacha item give @s gacha_demo:chest 1
```

控制台执行时把 `@s` 改为具体玩家名或 `@a`。数量可省略，范围1～64；背包不足时剩余物品掉落并指定给对应玩家。指令会应用定义中的完整外形组件；仅用原版 `/give` 写一个定义ID不会自动复制外形模板。

## 资源包改变外形

资源包处理视觉，数据包处理规则；仅安装资源包不会注册抽奖规则。

1. 定义中的 `minecraft:custom_model_data` 选择外形值。
2. 在载体模型中添加同值的原版 `overrides`。
3. 覆盖模型可使用自己的纹理、非方形贴图轮廓或三维JSON模型；遵守1.21.1原版模型格式和变换。

示例资源包把祈愿图腾的模型值1映射到 `gacha_demo:item/olive_ticket`，使用原版绿宝石纹理作为可直接加载的形状示例，不需要占位图片。模型值未设置的物品继续使用原模型。多个资源包覆盖同一载体模型时，需要在优先级最高的文件中合并 `overrides`。

默认箱子演出使用可开盖的ChestBlockEntity模型，不能被普通触发物图标替代。显式设置 `custom_model_data` 时尊重资源包自定义物品模型；静态JSON模型不会自动获得可分离箱盖的骨骼动画。需要开盖演出时，使用示例 `gacha_demo:chest` 或原版箱子模型路径。

## KubeJS

KubeJS 是可选依赖，插件入口为 `kubejs.plugins.txt`，未安装KubeJS时数据包和发放指令仍可用。接口已按项目当前依赖的 `KubeJSPlugin`、`BindingRegistry`、`KubeResourceGenerator` 源码核对。

提供脚本全局 `GachaDrawItems`：

| 方法 | 用途 |
| --- | --- |
| `define(event, id, definition)` | 在服务端数据生成事件中生成同格式的定义JSON，进入同一数据包读取流程 |
| `create(id)` | 在定义已经加载的服务端脚本回调中创建带完整组件的1个物品；未知ID抛错 |

把示例 `server_scripts/gacha_items.js` 放入实例的 `kubejs/server_scripts/` 后，可生成 `gacha_demo:script_ticket`。该脚本引用示例数据包中的卡池，因此仍需部署示例数据包。不要在脚本顶层、startup阶段或定义尚未加载时调用 `create`。

```javascript
ServerEvents.generateData('after_mods', event => {
    GachaDrawItems.define(event, 'gacha_demo:script_ticket', {
        card_pool: 'gacha_demo:custom_items',
        package: 'gacha_demo:triple',
        source: { gacha_type: 'gachaaddiction:modern_2' },
        item: {
            id: 'gachaaddiction:wish_totem',
            components: { 'minecraft:custom_model_data': 1 }
        }
    })
})
```

在已有服务端玩家事件回调中，可通过 `event.player.give(GachaDrawItems.create('gacha_demo:script_ticket'))` 发放；示例脚本本身不添加登录发奖事件。也可使用 `/gacha item give` 发放脚本定义。

## 动画与光效调整

- 图腾停稳朝向与原版FIXED模型变换配合，最终保持正面；末段使用五次平滑曲线。
- 箱子入场采用同一五次曲线，首尾速度和加速度归零，避免拼接处曲率突然变化。箱盖开度直接接入箱盖与锁扣模型绘制参数，保留原版开盖缓动；演出外返回原参数。
- 箱子和图腾物品的主光、补光改为来自观察方向的正面光，绘制结束恢复GUI物品光照。
- 背景光横向拉伸并收窄两端；中心柔和遮罩抑制角度射线，避免汇聚成尖点；亮度以连续正弦脉动。
- 倒影仅捕获对象本身，垂直翻转、压扁和渐隐，不捕获背景；对象悬浮描边不包含倒影。对象到达结束位置后，倒影平滑出现。
