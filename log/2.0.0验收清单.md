## 记录规则

本表使用CUR-前缀与旧文档用例ID区分。没有执行记录的场景全部保持未执行。代码已实现、IDEA无错误、Data完成、用户确认过某张画面正常，均不能替代完整场景通过记录。运行游戏、测试、重载或故障注入须按用户另行授权范围执行。

执行时记录代码/模组版本、双端及可选模组组合、世界副本、命令、操作、预期与实际结果、日志或截图。状态只用未执行、通过、失败、受阻、不适用；失败和受阻须写原因。

## 可直接使用的命令入口

播报场景先限定于当前已接入的真实容器及现有战利品袋/包链路。FTB奖励、公开卡池和专用绑定道具的独立结果链尚未接入播报，扩展范围单列主计划，不把未实现入口写成现有验收预期。

```text
/gacha open
/gacha inbox
/gacha inbox claim <transaction_uuid>
/gacha admin workbench
/gacha admin list reward_pools
/gacha admin list card_pools
/gacha admin list execution_plans
/gacha admin list request_presets
/gacha admin describe probability <reward_pool|table> <id>
/gacha reload
/gacha test reward_pool <targets> <preset_id>
/gacha test reward_pool_direct <targets> <pool_id> <rounds> <parameters_json>
/gacha test execution_plan <targets> <plan_id> <parameters_json>
/gacha test execution_plan_rounds <targets> <plan_id> <rounds> <parameters_json>
```

尖括号为占位参数，不能原样执行。`/gacha test`会向目标实际投递奖励，不是无副作用预览。资源包发送沿用`/gacha admin resource_pack <targets> "<url>" <sha1> <true|false>`，发送成功不等于下载或加载成功。不存在`/gacha draw`及旧的`admin edit/draft/publish/card_pool`命令。

模组内置的单抽/三连抽示例提供`gacha_test:secondary_demo`卡池和`gacha_test:single`、`gacha_test:triple`套餐，无需另装数据包；[独立数据包](test-packs/secondary-interactions.zip)保留供旧版使用。它只覆盖动画和基础结算，不覆盖动态参数、保底、复杂规则或故障恢复；加入内置资源不代表上述场景已经通过游戏验收。
